# NodeExporter-autoinstaller

Установщик **Prometheus node_exporter 1.12.1** для Linux с systemd.
Поддерживает установку, повторный запуск и обновление прежнего сервиса `exporterd`.

## Требования

- Linux с работающим systemd и доступом root через `sudo`.
- `bash`, `curl`, доверенные CA-сертификаты, `tar`, `gzip`, `sha256sum`, `flock`,
  `useradd`, `getent` и стандартные файловые утилиты.
- Доступ по HTTPS к GitHub Releases и адресам загрузки, на которые GitHub перенаправляет запросы.

Например, для Debian/Ubuntu:

```bash
sudo apt-get update
sudo apt-get install -y curl ca-certificates tar gzip coreutils util-linux passwd
```

Архитектура определяется автоматически: amd64, arm64, armv7, armv6, 386,
ppc64le, s390x, riscv64. Сам релиз должен содержать архив для выбранной архитектуры.
Интеграционные тесты выполнялись на Linux amd64.

## Установка

Сначала скачайте файл, затем запустите его отдельным процессом:

```bash
curl --fail --show-error --location --proto '=https' --proto-redir '=https' \
  https://raw.githubusercontent.com/g7AzaZLO/NodeExporter-autoinstaller/main/NodeExporter-auto-install.sh \
  --output NodeExporter-auto-install.sh
sudo bash NodeExporter-auto-install.sh
```

Старая команда `. <(wget ...)` больше не используется: скрипт нельзя подключать
через `source` или `.`. Для воспроизводимой установки замените `main` в URL
установщика на нужный SHA коммита. Версия самого exporter закреплена в скрипте.

По умолчанию новая установка слушает **127.0.0.1:9100**. Это подходит, если
Prometheus работает на том же сервере и имеет доступ к его loopback-интерфейсу.
Если Prometheus находится в контейнере, его localhost относится к контейнеру;
настройте доступ к адресу хоста отдельно.

Для удалённого Prometheus укажите **приватный адрес сервера с exporter**
(замените `10.0.0.10` на свой адрес):

```bash
sudo bash NodeExporter-auto-install.sh --listen-address 10.0.0.10:9100
```

Поддерживается IPv6, например `--listen-address '[::1]:9100'`.
Адреса `0.0.0.0:9100` и `[::]:9100` явно включают прослушивание всех интерфейсов;
используйте их только с подходящими сетевыми ограничениями.

Скрипт **не меняет и не включает firewall**. При использовании UFW можно
разрешить только конкретный Prometheus (`10.0.0.5` — его адрес):

```bash
sudo ufw allow proto tcp from 10.0.0.5 to 10.0.0.10 port 9100
sudo ufw status numbered
```

Прежний установщик добавлял общее правило `ufw allow 9100`. Новая версия его
автоматически не удаляет: проверьте существующие правила и удалите ненужное
общее разрешение. Для доступа через Интернет отдельно настройте TLS/аутентификацию
или защищённую сеть; этот установщик настраивает HTTP endpoint.

## Обновление и настройки

Повторно выполните скачанный установщик. Он скачивает точный релиз, проверяет
архив по официальному `sha256sums.txt`, подготавливает файлы и перезапускает
**тот же сервис `exporterd.service`**. При неудачном запуске или проверке метрик
восстанавливаются прежние бинарник, конфигурация, unit, состояние автозапуска
и активность сервиса. Ошибка возвращается вызывающему процессу.

Адрес хранится в `/etc/default/exporterd`:

```ini
LISTEN_ADDRESS=127.0.0.1:9100
```

При повторной установке без `--listen-address` он сохраняется. Значение нужно
писать без кавычек и пробелов. Другие настройки и комментарии сохраняются.
Если адрес изменён вручную, выполните `sudo systemctl restart exporterd`.

Другая точная версия устанавливается явно:

```bash
sudo bash NodeExporter-auto-install.sh --version 1.12.1
bash NodeExporter-auto-install.sh --help
```

Сервис запускается от системного пользователя `node_exporter` без возможности
входа. Бинарник устанавливается в `/usr/local/bin/node_exporter`, unit — в
`/etc/systemd/system/exporterd.service`. Старая копия `/usr/bin/node_exporter`
не удаляется, чтобы не затронуть другие сервисы. Одновременные установки
блокируются через `flock`.

**При переходе со старого установщика**, если `/etc/default/exporterd` ещё нет,
используется новый адрес по умолчанию: localhost. Для сохранения удалённого
сбора сразу передайте нужный `--listen-address`. Существующий unit заменяется;
настроенные администратором systemd drop-in файлы сохраняются. Сохраните свои
нестандартные параметры запуска перед миграцией. Созданная служебная учётная
запись может остаться после неудачной установки. При неполном откате скрипт
сообщит путь к сохранённым резервным копиям.

## Проверка

```bash
sudo systemctl status exporterd --no-pager
curl --fail http://127.0.0.1:9100/metrics
sudo journalctl -u exporterd -n 50 --no-pager
```

Для своего адреса замените localhost в команде. Установщик проверяет не только
активность сервиса, но и наличие `node_exporter_build_info` с нужной версией
в реальном ответе `/metrics`.

Для [дашборда G7](https://github.com/g7AzaZLO/grafana_dashboard) Prometheus
должен дополнительно присваивать целям метки `label` и `origin_prometheus`.
Сам node_exporter эти метки не добавляет.

## Тесты

```bash
bash tests/run.sh
```

Нужны Docker и curl. Тесты скачивают официальный архив с проверкой SHA-256,
собирают Ubuntu-контейнер и запускают его без сети. Проверяются ShellCheck,
синтаксис unit через `systemd-analyze verify`, настоящие CPU/memory/build-метрики
из exporter, запуск от непривилегированного пользователя, повторная установка,
миграция старого сервиса, повреждённая загрузка, неверные параметры и откат.

В тестовом контейнере systemd не работает как PID 1: для управления процессом
используется тестовый адаптер `systemctl`, который запускает настоящий exporter.
Поэтому тесты не проверяют применение ограничений systemd во время выполнения.
Аккаунты, сервисы и firewall машины, на которой запускаются тесты, не меняются.
